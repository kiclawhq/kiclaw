## What is KiClaw?

KiClaw is a file-first [Model Context Protocol](https://modelcontextprotocol.io/) server for KiCad. It gives an AI agent a reliable loop around a project: inspect, snapshot, make a constrained edit, run KiCad's own checks, and inspect the resulting diff.

It is intentionally honest about its capabilities. Board statistics come from lightweight S-expression parsing and are marked `approximate`; ERC, DRC, Gerber, drill, and SVG outputs are generated by KiCad itself.

### Product experience (split screen)

```text
LEFT:  terminal  —  user prompts AI / kiclaw chat
RIGHT: KiCad     —  PCB / schematic canvas
```

```bash
# Open the hybrid workbench (launch KiCad, open board, layout, then chat)
kiclaw start /path/to/project
# or: kiclaw workbench /path/to/project

# Create a new board project and open the workbench
kiclaw start --new MyCustomPCB --dir ~/Documents

# Left side: local command terminal (no cloud model required)
kiclaw chat

# Left side: full AI tools (connect Claude / Codex / Cursor MCP here)
kiclaw serve
# after workbench: kiclaw workbench --then serve
```

Then say things like *“make me a custom PCB…”* in the AI client. The agent calls MCP tools; **mutation results include `hybrid_live` / `user_message`** (what changed + where to look + reload path). KiCad on the right updates via best-effort IPC when the API Server is enabled, otherwise after file reload — we never claim full GUI puppetry.

## Installation

### Prerequisites

- Python 3.10 or newer.
- [uv](https://docs.astral.sh/uv/) for reproducible environment management.
- KiCad 9 or 10 for native DRC/ERC and export verification. On macOS, KiClaw discovers the bundled `kicad-cli` automatically.

### Install and verify

From PyPI (recommended for Python environments):

```bash
python -m pip install kiclaw
kiclaw doctor
```

From source with a locked environment:

```bash
uv sync --no-editable --extra dev
uv run --no-editable kiclaw doctor
uv run --no-editable kiclaw compatibility /absolute/path/to/project
uv run --no-editable kiclaw review /absolute/path/to/project
uv run --no-editable kiclaw review /absolute/path/to/project --output kiclaw-review.json --fail-on-warning
uv run --no-editable kiclaw dfm /absolute/path/to/board.kicad_pcb
uv run --no-editable kiclaw emc /absolute/path/to/board.kicad_pcb
uv run --no-editable kiclaw si /absolute/path/to/board.kicad_pcb
uv run --no-editable kiclaw thermal /absolute/path/to/board.kicad_pcb
uv run --no-editable kiclaw analyze /absolute/path/to/board.kicad_pcb
uv run --no-editable kiclaw analyze /absolute/path/to/board.kicad_pcb --packs power_tree,protection,ground --output analysis.json
uv run --no-editable kiclaw spice /absolute/path/to/circuit.cir
uv run --no-editable kiclaw evidence /absolute/path/to/datasheet.txt --claim "5 V" --claim "-40 C to 85 C"
uv run --no-editable kiclaw schematic-check /absolute/path/to/design.kicad_sch
uv run --no-editable kiclaw schematic-add-wire /absolute/path/to/design.kicad_sch 100 100 110 100
uv run --no-editable kiclaw schematic-add-component /absolute/path/to/design.kicad_sch Connector_Generic:Conn_01x28 P4 240 50 --value HEADER
uv run --no-editable kiclaw schematic-add-custom-component /absolute/path/to/design.kicad_sch Connector_Generic:Conn_01x28 KiClaw:CustomHeader28 P4 240 50 --value HEADER
uv run --no-editable kiclaw start /absolute/path/to/project
uv run --no-editable kiclaw chat
uv run --no-editable kiclaw serve
```

The `doctor` command prints the detected KiCad version and available backends. Use `compatibility` for a project-specific matrix and `review` for a machine-readable engineering report.

### Configure an MCP client

For Codex or another stdio MCP client, use:

```text
uv run --directory /absolute/path/to/kiclaw --no-editable kiclaw serve
```

The server advertises its tools, the `kicad://capabilities` resource, and a manufacturing-review prompt during MCP initialization. Use `capability_report` first, then inspect the project before any mutation.

While the server is running, KiClaw writes operator progress to `stderr` so MCP's JSON-RPC stream remains clean. A connected terminal shows messages such as `MCP server ready`, `→ review_project`, and `✓ review_project (1.42s)`; use `serve --verbose` for additional runtime detail.

### npm launcher

If your organization standardizes on Node.js tooling, the companion npm package launches the same Python MCP server through `uvx`:

```bash
npx -y kiclaw doctor
npx -y kiclaw serve
```

The npm package is a launcher, so Python, `uv` (preferred), and KiCad remain runtime prerequisites. It does not create a second implementation of the engineering tools.

On macOS, KiClaw automatically detects KiCad's bundled `kicad-cli`; no `PATH` changes are required.

To enable the live IPC edit, install the optional extra (`uv sync --no-editable --extra ipc`) and turn on KiCad's API Server in Preferences → Plugins → API Server, then restart KiCad. KiCad 10 does not provide a headless API server, so the GUI must be running. If the server is disabled or unreachable, `ipc_move_footprint` returns an explicit unavailable result and does not touch the board file.

## Tool groups

- Project inspection and evidence: `open_project`, `project_info`, `compatibility_report`, `datasheet_evidence`, `pcb_statistics`, `list_footprints`, `list_nets`, `schematic_summary`, `schematic_roundtrip_check`
- Verification and review: `run_drc`, `run_erc`, `run_dfm`, `run_emc`, `run_si`, `run_thermal`, `run_analysis`, `spice_capability`, `run_spice`, `review_board`, `review_project`, `export_gerbers`, `export_drill`, `export_svg`, `export_ipc2581`
- Live-session observability: `capability_report`, `ipc_session_info`, `ipc_board_status`, `backend_session_info`, `launch_kicad`, `live_status`, `start_engineering_session`
- Reasoning loop: `get_board_status`, `snapshot_create`, `snapshot_list`, `snapshot_restore`, `verify_last_action`
- Guarded edits: `add_track`, `move_footprint` (prefers live IPC when available; otherwise file/CLI fallback)
- Backend policy: `pcb_backend_policy` reports the non-mutating IPC-versus-file selection and its reason
- Guarded schematic edits: `add_wire`, `add_component`, `add_custom_component`
- Live IPC edit: `ipc_move_footprint` (native undoable move; save remains explicit)
- Progressive disclosure: `list_tool_categories`, `find_tool`, `run_tool`

`review_board` combines KiCad's native DRC JSON with conservative deterministic checks. `review_project` aggregates every board and schematic into one JSON report with severity, evidence, confidence, and source. Warnings are visible but do not block a review; errors and unknown verification states do.

`run_analysis` (CLI: `kiclaw analyze`) runs the Deep Analysis Layer: power-net inventory, decoupling proximity, connector protection audit, net-name clusters, ground strategy, and connectivity gaps. Findings are structural triage with confidence labels — not datasheet Vout, ESD certification, or SI/EMC lab results. Findings merge into `review_board` / `review_project` under `checks.analysis`.

Every file-backed mutator accepts absolute or relative project paths, rejects stale expected hashes, writes an auditable transaction manifest, preserves a recoverable snapshot under `.kiclaw/snapshots`, and verifies the intended semantic change before returning success. Install the optional `ipc` extra to enable the official `kicad-python` boundary.

## Project status

The current `0.1.0` baseline covers the documented file-first workflow, deep analysis, expanded MCP surface, manufacturing exports, and the split-screen workbench entry (`kiclaw start` / `kiclaw chat` / `kiclaw serve`). A final design sign-off still requires a real project supplied by the user; this repository intentionally does not contain a product board or schematic.

Deliberately outside guaranteed live-canvas coverage: full remote control of every KiCad dialog, arbitrary schematic geometry generation, datasheet-to-design inference, full routing, stackup-aware SI/PI, EMC certification, and multi-version laboratory qualification. Conservative indicators expose evidence and limitations instead of presenting heuristics as engineering guarantees.

## Architecture

```text
MCP client / CLI (kiclaw start | chat | serve)
        |
        v
server.py / workbench  ── public tools, resource, prompt, progressive router
        |
        v
core + analysis + edit + libraries  ── discovery, snapshots, reviews, exports
        |
        +── KiCad CLI (DRC/ERC/Gerber/drill/SVG/IPC-2581/BOM/pos)
        +── file backend (atomic, hash-guarded edits)
        +── optional kicad-python IPC backend (live PCB Editor only)
```

Domain logic is intentionally testable without MCP. File-derived statistics are always marked approximate; KiCad-native checks are the source of truth for verification and manufacturing exports.

## Development

```bash
# Use a workspace-local environment and the locked dependency graph.
uv sync --locked --no-editable --extra dev

# Fast host and CLI smoke checks.
uv run --locked --no-editable kiclaw --help
uv run --locked --no-editable kiclaw doctor

# Full automated verification.
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 uv run --locked --no-editable pytest -q
```

The GitHub Actions workflow runs the test suite and emits a machine-readable `kiclaw-review.json` artifact. For a real project, run `compatibility` first, then `review`; pass `--fail-on-warning` only when the project policy treats warnings as release blockers. Keep `.kiclaw/` transaction state out of source control.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the change workflow and [CHANGELOG.md](CHANGELOG.md) for release notes. The reusable agent procedure is documented in [skills/kiclaw-agent/SKILL.md](skills/kiclaw-agent/SKILL.md).

## Release and support policy

KiClaw follows semantic versioning for its public CLI/MCP surface. Changes to tool names, arguments, result schemas, or safety semantics require a changelog entry and regression tests. A release is ready only when the locked test suite passes, the CLI smoke checks pass, and a representative KiCad project has a recorded compatibility/review report. KiCad-native output and the host-specific capability matrix must be retained with manufacturing evidence when this tool is used in a controlled engineering workflow.
